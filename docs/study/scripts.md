# scripts/

| Script | Purpose | How it works / gotcha |
|---|---|---|
| `verify.py` | Reproducibility proof (brief step 10) | `python scripts/verify.py [scale]` builds the whole package twice into temp dirs with the fixed seed and compares every file (lines + SHA-256); exit 1 on any difference or if validation does not flag exactly the planted defects |
| `summarize_data.py` | Compact look at generated CSVs | Prints row count, columns and 3 sample rows per file, so raw data never needs reading (also saves tokens) |
| `post_edit.py` | Claude Code PostToolUse hook | Reads the hook JSON from stdin; for edited `.py` files runs ruff format, ruff check --fix, pytest -x; exit 2 (blocking feedback) only on real failures; exit 5 (no tests collected) is tolerated |

| `export_prompts.py` | Prompt history for the submission (FAQ 6) | Reads this project's Claude Code transcripts and writes redacted markdown to `ai-transparency/prompt-history/`: user prompts per session, subagent prompts, WebFetch helper prompts. Keeps user text verbatim; strips system reminders, IDE notices and tool output; redacts OS username, e-mails and token patterns; exits 1 if a secret-like pattern remains. Rebuilds from the transcripts every run (deterministic) but refuses to shrink the committed history unless `--force` is passed. Re-run before the final push and read the output first |
| `app.py` (repo root) | The minimal view (SPEC deliverable 11) | `streamlit run app.py` (needs `pip install -e ".[ui]"`). Rendering only: tabs in order: Submit a claim (app_intake.py), Decisions (filters), Exceptions (counts + rows), Claim timeline (history, rule trace, what would make it payable, details), Metrics (rates, cycle times, amounts, rule impact, straight-through rate, approver workload, docs-pending aging, threshold sensitivity, precision/recall), Realism (distributions), Reproducibility (fixed seed, dataset checksum, rebuild button) and Quality and data (app_quality.py). All data from `claimsgen.view_data`; scale: starter 0.05, medium 0.25 or full 1.0, built in memory and cached |
| `app_intake.py` (repo root) | The Submit a claim tab of the view | Rendering only: example picker, JSON text area and a small form, then `intake.parse_and_validate` and `whatif.evaluate` (the real engine on a copy of the dataset, never changing it). Shows status, decision, rule, payable, approval route, rule trace, counterfactual, timeline, schema rows and the horizon; a "Request the missing documents" button on pend_docs shows the pend-and-resume second assessment; results are kept in `st.session_state["intake_results"]`. Widget keys start with `intake_`. No AI, no ground_truth, no clock. Headless test: `tests/test_app_intake.py` |
| `app_quality.py` (repo root) | The Quality and data tab of the view | Rendering only: validation checks, planted defects vs flagged, edge-case counts, the answer key (labelled scoring-only), data dictionary, rule catalogue and a table browser. Widget keys start with `q_`. Headless test: `tests/test_app_quality.py` |

Wired in `.claude/settings.json` (hook) and `.claude/commands/verify.md` (`/verify`).
